# Python Runner — 下载引擎优化方案

> 编制日期：2026-06-03
> 优化目标：应用自更新下载流程

---

## 现状分析

### 当前下载流程

```
Flutter 层（app_update_manager.dart）
  ├─ 拼接下载 URL（可带 GitHub 镜像前缀）
  ├─ showDialog 展示进度弹窗
  └─ 监听 installProgressStream 获取进度
       │
Kotlin 层（MainActivity.kt :: handleDownloadAndInstallApk）
  ├─ 权限检查（canRequestPackageInstalls）
  ├─ 单个 HttpURLConnection 串行下载
  ├─ 8KB 固定 buffer 逐块读写
  ├─ installSink 回传进度给 Flutter
  └─ FileProvider → ACTION_VIEW 触发系统安装器
```

### 核心问题

| 问题 | 现状 | 影响 |
|------|------|------|
| 单连接下载 | 1 个 HttpURLConnection × 8KB buffer | 镜像/代理场景下被限速，155MB APK 耗时长 |
| 无断点续传 | 断网后 `apkFile.delete()` 从零开始 | 用户下载到 80% 断网必须重下全部 |
| 无失败重试 | 连接失败直接 throw | 弱网环境一次超时就彻底失败 |
| 无取消/暂停 | 弹窗创建后只能等完成或杀进程 | 用户无法控制下载过程 |
| 无速度显示 | 只显示已下载/总量 | 用户无法判断还要等多久 |
| 共用 EventChannel | 下载进度和安装进度同一条通道 | 并发操作时进度事件会混在一起 |
| 无校验 | 下载完成直接安装 | 文件损坏/不完整时安装失败难以排查 |

## 优化分三个阶段

---

## 阶段一：断点续传 + 自动重试

**收益：** 断网不用重头下，弱网不再一次失败就结束

### 1.1 新增 `DownloadTask` 数据模型

```kotlin
data class DownloadTask(
    val url: String,
    val filePath: String,
    val totalBytes: Long = -1,       // -1 = 未知
    val downloadedBytes: Long = 0,
    val etag: String = "",           // 校验服务端文件是否变更
    val status: TaskStatus = TaskStatus.PENDING,
    val retryCount: Int = 0,
    val lastError: String = ""
)

enum class TaskStatus {
    PENDING,       // 等待开始
    DOWNLOADING,   // 下载中
    PAUSED,        // 用户暂停
    COMPLETED,     // 完成
    FAILED         // 失败
}
```

### 1.2 任务清单

| 任务 | 层级 | 说明 |
|------|------|------|
| 新建 `DownloadTask` 模型 | Kotlin | 记录 URL、文件路径、总大小、已下载字节数、ETag、状态 |
| 新建 `DownloadManager` 类 | Kotlin | 封装下载逻辑，与 MainActivity 解耦 |
| 实现 HTTP Range 续传 | Kotlin | 发送 `Range: bytes=xxx-`，处理 206 Partial Content |
| 进度持久化 | Kotlin | 每 256KB 写一次 `.task_state.json` 到下载目录 |
| 断点恢复 | Kotlin | 启动下载前检查本地状态文件，有则从断点继续 |
| ETag 校验 | Kotlin | HEAD 请求对比 ETag，文件变更则删除旧文件重新开始 |
| 指数退避重试 | Kotlin | 失败后重试 3 次，间隔 2s → 4s → 8s |
| Flutter 桥接 | Dart | `native_bridge.dart` 新增 `pauseDownload` / `resumeDownload` / `cancelDownload` |
| UI 增加暂停/取消/重试 | Dart | 进度弹窗增加按钮；失败时显示"重试"而非直接关闭 |

### 1.3 下载流程

```
开始下载
  │
  ├─ 检查本地是否有 .task_state.json
  │   ├─ 有 + ETag 未变 → Range 续传
  │   └─ 有 + ETag 变了 → 删旧文件，从零下载
  │
  └─ 无状态文件 → HEAD 获取 Content-Length + ETag
      │
      ├─ 循环读写 buffer（8KB → 64KB）
      │   ├─ 每 256KB → 更新进度 + 写 .task_state.json
      │   └─ 网络异常 → 指数退避重试（最多 3 次）
      │
      ├─ 完成 → 删除 .task_state.json → 触发安装
      └─ 3 次重试均失败 → 标记 FAILED → UI 显示重试按钮
```

## 阶段二：多线程分段下载

**收益：** 多条 TCP 通道突破单连接限速，下载速度成倍提升

### 2.1 前置验证

| 验证项 | 方法 | 结论 |
|--------|------|------|
| GitHub CDN Range 支持 | HEAD 请求 + `Range: bytes=0-1023`，检查 206 响应 | objects.githubusercontent.com 通常支持 |
| 镜像站 Range 支持 | 同上，针对 ghfast.top 等常用镜像 | 大部分镜像转发了原始头 |

不支持 Range 的情况下自动退化为阶段一的单连接续传模式。

### 2.2 任务清单

| 任务 | 层级 | 说明 |
|------|------|------|
| Range 支持探测 | Kotlin | HEAD + Range 测试，结果缓存，不支持则退化 |
| 分段调度器 | Kotlin | 将文件均分为 N 段，每段分配独立协程 |
| RandomAccessFile 写入 | Kotlin | 各协程写入同一文件的不同区域，无需拼接 |
| 分段进度汇总 | Kotlin | `AtomicLong` 累加各段已下载字节，统一上报 |
| 分段失败独立重试 | Kotlin | 单段失败不影响其他段，该段单独重试 |
| 可配置并发数 | Dart | 设置页新增「下载线程数」选项（1~8，默认 4） |
| 连接超时可配置 | Dart | 设置页新增「下载超时」选项 |

### 2.3 架构设计

```
┌─ DownloadManager（单例）──────────────────────────┐
│                                                    │
│  文件 = 155MB                                      │
│  分段数 = 4                                        │
│                                                    │
│  Segment[0]  bytes [0, 40MB)      → Coroutine-1   │
│  Segment[1]  bytes [40MB, 80MB)   → Coroutine-2   │
│  Segment[2]  bytes [80MB, 120MB)  → Coroutine-3   │
│  Segment[3]  bytes [120MB, 155MB) → Coroutine-4   │
│                                                    │
│  progressBytes: AtomicLong  ← 各协程 atomic 累加    │
│  sink: EventChannel.EventSink ← 汇总上报 Flutter    │
│                                                    │
│  策略自适应：                                        │
│    ├─ Range 支持 → 多协程分段下载                    │
│    └─ Range 不支持 → 退化为单连接 + 阶段一续传       │
└────────────────────────────────────────────────────┘
```

### 2.4 分段策略

```
分段数 = min(用户配置线程数, ceil(文件大小 / 10MB))
每段大小 ≈ 总大小 / 分段数
最后一段 = 总大小 - 前 N-1 段之和

例：155MB APK，4 线程
  段0: [0, 39MB)        → 39MB
  段1: [39MB, 78MB)     → 39MB
  段2: [78MB, 117MB)    → 39MB
  段3: [117MB, 155MB)   → 38MB
```

各段写入同一文件的不同偏移位置（`RandomAccessFile.seek(offset)`），下载完成后无需额外拼接。

### 2.5 分段续传状态

```json
{
  "url": "https://github.com/.../app-release.apk",
  "totalBytes": 163057664,
  "etag": "\"abc123\"",
  "segments": [
    {"start": 0, "end": 40894463, "downloaded": 40894463, "status": "completed"},
    {"start": 40894464, "end": 81788927, "downloaded": 26214400, "status": "downloading"},
    {"start": 81788928, "end": 122683391, "downloaded": 0, "status": "pending"},
    {"start": 122683392, "end": 163057663, "downloaded": 0, "status": "pending"}
  ]
}
```

恢复时从各段的 `downloaded` 位置继续，不必重头开始。

### 3.2 新增交互元素

| 元素 | 说明 |
|------|------|

| **失败重试** | 弹窗不关闭，显示"重试"按钮 |

| 剩余时间估算 | Dart | 基于速率和剩余大小计算，UI 显示 |
| 分段状态指示 UI | Dart | 每个分段一个彩色小方块，实时更新 |

## 动画优化方案

> 分析日期：2026-06-04
> 基于 `lib/` 全部页面的动画代码审查

---

### 现状总览

| 页面 | 现有动画 | 类型 |
|------|---------|------|
| 启动页 | Logo 淡入 + 缩放弹跳 (900ms) | 显式 AnimationController |
| Tab 切换 | 淡入 + 微滑 (250ms) | AnimatedSwitcher |
| 脚本列表 | 卡片交错淡入上滑 | TweenAnimationBuilder |
| 所有页面跳转 | 系统默认右滑 | MaterialPageRoute |
| 所有对话框 | 系统默认缩放淡入 | showDialog 默认 |
| 所有底部弹窗 | 系统默认上滑 | showModalBottomSheet 默认 |
| SnackBar | 系统默认底部滑入 | Flutter 内置 |

**核心问题：** 全 app 没有统一的动画语言，18 处页面跳转全部用系统默认右滑，对话框/弹窗也是 Flutter 默认效果，缺乏品牌一致性和视觉节奏感。

---

### 问题一：页面转场全部千篇一律

**现状：** 所有 `Navigator.push` 都用 `MaterialPageRoute`，用户在 3 个 Tab 之间跳转 8+ 个子页面时，看到的永远是"从右边滑入"。

**优化方案：**

| 场景 | 当前 | 建议 | 效果 |
|------|------|------|------|
| 脚本列表 → 编辑器 | 右滑 | **共享轴变换** (Shared Axis) | 左右方向暗示"深入编辑" |
| 脚本列表 → 运行终端 | 右滑 | **淡入 + 上滑** (FadeThrough) | 向上暗示"开始执行" |
| 编辑器 → 运行终端 | 右滑 | **放大淡入** (Scale) | 缩放暗示"启动运行" |
| 设置页入口 | 底部滑入 | 保持现有 fullscreenDialog | 合理，无需改 |
| 网络检查 → 详情 | 右滑 | **淡入** (Fade) | 简洁过渡，避免左右反复 |
| 任何位置 → 系统日志 | 右滑 | 保持右滑 | 信息层级，右滑合理 |

**实现方式：** 定义一个 `AppRoutes` 工具类封装 `PageRouteBuilder`：

```dart
// 统一的转场定义
class AppPageTransitions {
  static Route<T> fadeThrough<T>(Widget page) {
    return PageRouteBuilder(
      transitionDuration: Duration(milliseconds: 300),
      reverseTransitionDuration: Duration(milliseconds: 250),
      pageBuilder: (_, __, ___) => page,
      transitionsBuilder: (_, anim, __, child) {
        return FadeTransition(
          opacity: CurvedAnimation(parent: anim, curve: Curves.easeOut),
          child: child,
        );
      },
    );
  }

  static Route<T> sharedAxisLeftRight<T>(Widget page) {
    return PageRouteBuilder(
      transitionDuration: Duration(milliseconds: 300),
      pageBuilder: (_, __, ___) => page,
      transitionsBuilder: (_, anim, __, child) {
        final slide = Tween(begin: Offset(0.3, 0), end: Offset.zero)
            .chain(CurveTween(curve: Curves.easeOutCubic));
        return SlideTransition(
          position: anim.drive(slide),
          child: FadeTransition(opacity: anim, child: child),
        );
      },
    );
  }

  static Route<T> scaleIn<T>(Widget page) {
    return PageRouteBuilder(
      transitionDuration: Duration(milliseconds: 350),
      pageBuilder: (_, __, ___) => page,
      transitionsBuilder: (_, anim, __, child) {
        return ScaleTransition(
          scale: CurvedAnimation(parent: anim, curve: Curves.easeOutBack),
          child: FadeTransition(opacity: anim, child: child),
        );
      },
    );
  }
}
```

### 问题二：脚本列表交错动画有性能隐患

**现状：** `script_list_page.dart:657-666`

```dart
duration: Duration(milliseconds: 200 + index * 30),
```

- 30 个脚本时最后一个动画 1100ms，用户感知为"卡顿"
- `TweenAnimationBuilder` 每帧重建整个子树（包括 `Opacity` + `Transform.translate`），复杂卡片在低端机上掉帧

**优化方案：**

| 项 | 现状 | 改进 |
|----|------|------|
| 动画时长 | 200 + index*30，无上限 | **上限 500ms**，前 5 个依次出现，之后同时出现 |
| 子树重建 | 每帧全量重建 | 用 `RepaintBoundary` 包裹卡片，隔离重绘区域 |
| 动画方式 | `Opacity` + `Transform.translate` | 改为 `AnimatedOpacity` + `Transform`，减少每帧开销 |

```dart
// 改进后
Duration(milliseconds: (200 + index * 40).clamp(200, 500))
```

### 问题三：启动页动画有死代码

**现状：** `main.dart:288`

```dart
_fadeOut = CurvedAnimation(parent: _animController, curve: Curves.easeIn);
```

声明了 `_fadeOut` 但 `build()` 中从未使用。`CurvedAnimation` 会注册控制器监听器，浪费资源。

### 问题四：启动页退出无动画

**现状：** 启动页 Logo 淡入+缩放做得很精细，但退出到主页面时直接硬切（`1200ms` 后替换 widget），没有过渡。

**优化方案：** 用 `AnimatedSwitcher` 包裹启动页 → 主页面的切换，添加淡出效果：

```dart
AnimatedSwitcher(

```

### 问题五：对话框/底部弹窗缺乏层次感

**现状：** 全部使用 Flutter 默认的 `showDialog` / `showModalBottomSheet`，效果是统一的缩放淡入 / 上滑，所有弹窗看起来一样。

**优化方案：**

| 弹窗类型 | 改进 |
|---------|------|
| **确认删除** (破坏性操作) | 添加红色微光脉冲效果，增强警示感 |
| **过滤器底部弹窗** | 加快动画至 200ms，使用 `easeOutQuart` 曲线 |
| **新建脚本对话框** | 保持默认（输入型弹窗适合温和动画） |
| **设置项确认对话框** | 保持默认 |

### 问题六：终端自动滚动无动画

**现状：** `terminal_view.dart` 中新输出到达时直接 `jumpTo` 跳到底部，内容突然跳动。

**优化方案：** 当自动滚动启用时，改用 `animateTo` 平滑滚动：

```dart
void _scrollToBottom() {
  if (!_scrollController.hasClients) return;
  if (_autoScroll) {
    _scrollController.animateTo(
      _scrollController.position.maxScrollExtent,
      duration: Duration(milliseconds: 150),
      curve: Curves.easeOut,
    );
  } else {
    _scrollController.jumpTo(
      _scrollController.position.maxScrollExtent,
    );
  }
}
```

### 问题七：运行状态切换无视觉反馈

**现状：** 脚本运行结束时，顶部状态标签从"运行中"直接变成"已结束"，没有过渡。

**优化方案：** 用 `AnimatedSwitcher` 包裹状态文本，添加交叉淡入淡出：

```dart
AnimatedSwitcher(

  child: Text(
    statusText,

    style: TextStyle(...),
  ),
)
```

```
第二批（体验提升）

第三批（视觉丰富）
```
